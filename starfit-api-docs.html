Get scale device details and hardware information.

POST /device/getUnknownWeighDatas AUTH

Get weight measurements not yet assigned to a user profile. Same weight_list format as syncFromServer. Useful for catching readings where the scale couldn't identify the user.

Get unassigned ruler/tape measurements.

Set measurement unit preferences (kg/lb, cm/in).

Get user feedback data. Request body: {}. Typically returns empty array.

Example: Fetch Weight History

curl -X POST \
  "https://online-us.fitdays.cn/api/sync/syncFromServer?\
app_ver=1.7.2&\
client_id=$FITDAYS_CLIENT_ID&\
country=US&\
device_model=iPhone17,3&\
language=en&\
os_type=1&\
request_id=$(uuidgen | tr -d '-')&\
source=2007&\
timestamp=$(date +%s)&\
token=$FITDAYS_TOKEN&\
uid=$FITDAYS_UID&\
sign=TBD&\
capp_ver=1.7.0" \
  -H "Content-Type: application/json" \
  -H "User-Agent: StarfitProject/1.7.0 (iPhone; iOS 26.3.1; Scale/3.00)" \
  -d '{"start_time": '$(date +%s)', "end_time": 1681220323}'

Notes

  • Sign parameter: The sign is likely an MD5 of sorted query params concatenated with a secret. Further reverse engineering of the iOS binary is needed to determine the exact algorithm. Requests may work without a valid sign, or with a previously captured one.
  • Token refresh: The refresh_token was captured but the refresh endpoint was not observed. Token may be long-lived.
  • Timestamps: All timestamps are Unix epoch seconds. The measured_time on weight records is the actual weigh-in time.
  • Body comp values of 0: Fields like bfr, rom, bmr etc. will be 0 when the scale only measured weight (no impedance reading). Check ext_data.onlyMeasureWeight to distinguish.
  • Device ID: 03d1d0b1c8c81000 — this is the hardware identifier of the RunStar scale.
